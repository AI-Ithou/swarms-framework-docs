Use a decision model to select a support agent before generating a reply. A Choice question compares the agents' descriptions. A Noul question checks whether the task belongs to support. Only the selected agent runs after both policy checks pass.

## Set up

Use Python 3.10 or later and Git. Set both keys:

- `TYPESAFE_API_KEY` authenticates the `jev-latest` decision model used for routing
- `OPENAI_API_KEY` authenticates the `gpt-5.4` model used by the selected Swarms agent

<Warning>
Support for this API in published Swarms releases has not yet been verified. Install from the inspected GitHub source revision below instead of assuming your installed release includes `DecisionModel`.
</Warning>

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install "swarms @ git+https://github.com/kyegomez/swarms.git@c5e71b85ddc98c60951039c716970a72f61ea6db"
export TYPESAFE_API_KEY="your-typesafe-key"
export OPENAI_API_KEY="your-openai-key"
export SWARMS_TELEMETRY_ON=false
```

`SWARMS_TELEMETRY_ON=false` disables optional Swarms telemetry for this walkthrough. Keep both keys out of your script and version control. Your OpenAI account must have access to the configured agent model.

## Run the complete example

Save this as `agent_router.py`, then run `python agent_router.py`. From a checkout of this docs repository, you can also run `python examples/decision-models/code/agent_router.py`. Running the example sends every task to TypeSafe and sends accepted tasks to OpenAI; both providers may charge for API usage.

```python
"""Route a support task to one agent after scope and confidence checks."""

import json


def choose_route(answers: dict, agent_names: set[str]) -> tuple[str, str]:
    """Return an action and its message or agent name; no network calls."""
    if answers["in_scope"]["noul"] < 0.5:
        return "decline", "Declined: out of scope for support."

    decision = answers["agent"]
    if decision["confidence"] < 0.5:
        return "escalate", "Escalated to a human: routing confidence is below 0.5."
    if decision["choice"] not in agent_names:
        return "escalate", "Escalated to a human: the selected agent is unknown."
    return "run", decision["choice"]


def route(task: str, router, agents_by_name: dict) -> str:
    """Evaluate both routing questions, then run only the selected agent."""
    result = router.run(
        state=task,
        questions={
            "agent": {
                "type": "choice",
                "instructions": "Which agent should handle this request?",
                "criteria": {
                    agent.agent_name: agent.agent_description
                    for agent in agents_by_name.values()
                },
            },
            "in_scope": {
                "type": "noul",
                "instructions": (
                    "This is a request a software company's support team "
                    "should handle."
                ),
            },
        },
    )
    # Print the full decision response before any agent executes.
    print(json.dumps(result, indent=2))
    action, target = choose_route(result["answers"], set(agents_by_name))
    if action != "run":
        return target

    confidence = result["answers"]["agent"]["confidence"]
    print(f"Routing to {target} (confidence {confidence:.2f})")
    return agents_by_name[target].run(task)


def main() -> None:
    from swarms import Agent, DecisionModel

    agents = [
        Agent(
            agent_name="Billing-Agent",
            agent_description=(
                "Refunds, invoices, failed payments and subscription changes."
            ),
            system_prompt="You resolve billing questions clearly and briefly.",
            model_name="gpt-5.4",
            max_loops=1,
            output_type="str",
        ),
        Agent(
            agent_name="Technical-Agent",
            agent_description="Bugs, API errors, integrations and outages.",
            system_prompt="You debug technical problems step by step.",
            model_name="gpt-5.4",
            max_loops=1,
            output_type="str",
        ),
        Agent(
            agent_name="Sales-Agent",
            agent_description="Pricing, plan upgrades and new accounts.",
            system_prompt="You answer pricing and plan questions.",
            model_name="gpt-5.4",
            max_loops=1,
            output_type="str",
        ),
    ]
    agents_by_name = {agent.agent_name: agent for agent in agents}
    tasks = [
        "I was charged twice for my March invoice, can you refund one?",
        "Our webhook endpoint returns 500 since your API update this morning.",
        "What does the enterprise plan cost for 200 seats?",
        "Can you write my history essay on the French Revolution?",
    ]
    router = DecisionModel(model_name="jev-latest")
    try:
        for task in tasks:
            print(f"\nTask: {task}")
            print(route(task, router, agents_by_name))
    finally:
        router.close()


if __name__ == "__main__":
    main()
```

## Build the routing criteria

The Choice `criteria` dictionary maps each `Agent.agent_name` to its `Agent.agent_description`. Keep names unique and descriptions specific enough to distinguish billing, technical, and sales requests. You can add another agent without maintaining a separate list of routing descriptions.

A Choice question selects among the available agents. The separate `in_scope` Noul question lets your application decline unrelated tasks instead of executing a forced match. Both questions are sent in one decision-model request per task.

## Gate execution

`choose_route()` applies these checks in order:

1. `in_scope.noul` below `0.5`: decline the request without running an agent
2. Routing `confidence` below `0.5`: escalate to a human without running an agent
3. An unrecognized agent name: escalate instead of looking up an invalid key
4. Otherwise: call `run(task)` on exactly the chosen agent

This small demonstration reuses the agent instances. For independent customer conversations, create separate agents so conversation history is not shared across customers.

The first two checks use strict less-than comparisons: `0.5` passes each gate. These thresholds are application policy, not a calibrated correctness guarantee. Tune them with representative requests before using automated routing in production.

Decline and escalation paths return notices for your application to handle; they do not contact a human. The agents in this example have no tools to issue refunds or change accounts. `choose_route()` is a pure function you can test offline, and `route()` accepts the router and agent registry so tests can substitute local stand-ins.

## Inspect your run

<Note>
Live TypeSafe and OpenAI output has not yet been verified for this walkthrough. No fabricated routing probabilities or agent responses are presented as recorded output.
</Note>

For each task, the script prints the full routing response before any agent runs. You then see a decline or escalation notice, or the selected agent's name and generated reply. The four input tasks exercise billing, technical, sales, and unrelated requests, but their returned decisions depend on the live model.

The `finally` block closes the decision model's pooled HTTP client if routing or agent execution raises an error. No other agent is run as a fallback.
