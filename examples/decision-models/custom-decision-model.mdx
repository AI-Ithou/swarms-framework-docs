Use the same [DecisionModel](/api/decision-model) interface with a gateway, a pinned model version, or your own compatible service. Keep the provider's URL, model ID, and credentials together so a request reaches the intended service.

<Note>
This guide targets [Swarms commit `c5e71b8`](https://github.com/kyegomez/swarms/commit/c5e71b85ddc98c60951039c716970a72f61ea6db). Install from source until your PyPI release includes `DecisionModel`. The complete example below has not been verified against a live provider; it prints the actual response when you run it. The custom envelope is an illustrative protocol, not a deployed service.
</Note>

## Set up

```bash
python -m pip install "swarms @ git+https://github.com/kyegomez/swarms.git@c5e71b85ddc98c60951039c716970a72f61ea6db"
export SWARMS_TELEMETRY_ON=false
```

The command pins the implementation used here. To track the framework branch instead, use `python -m pip install git+https://github.com/kyegomez/swarms.git`. No `typesafe-sdk` dependency is needed. The telemetry setting disables optional Swarms telemetry for this walkthrough.

Configure the credential for only the mode you intend to run:

| Mode | Credential environment variable | Destination |
| --- | --- | --- |
| Pinned Jev | `TYPESAFE_API_KEY` | TypeSafe |
| OpenRouter | `OPENROUTER_API_KEY` | OpenRouter |
| Custom envelope | `CUSTOM_DECISION_API_KEY` | Your configured provider |

Use your environment or a secret manager; do not put keys in the example file. The [TypeSafe console](https://console.typesafe.ai/keys) and [OpenRouter keys page](https://openrouter.ai/settings/keys) manage those providers' credentials. API access and billing are separate from installing the Swarms package.

## Call Jev through OpenRouter

OpenRouter exposes a [TypeSafe-compatible API](https://docs.typesafe.ai/sdk/python/usage#configuring-the-base-url). It accepts the same typed questions, so you do not need a subclass:

```python
from swarms import DecisionModel

model = DecisionModel(
    base_url="https://openrouter.ai/api",
    endpoint="/v1/systemone",
    model_name="~typesafe/jev-latest",
    api_key_env="OPENROUTER_API_KEY",
)
```

The resulting evaluation URL is `https://openrouter.ai/api/v1/systemone`. Use the gateway's model ID and key. Do not send a TypeSafe key to OpenRouter. This configuration is for structured decisions, not the gateway's chat-completions endpoint.

## Pin a version

An alias can move to a newer model. Pin a version when you need to evaluate changes before adopting them:

```python
from swarms import DecisionModel

model = DecisionModel(model_name="jev-1.13.0")
```

This uses the direct TypeSafe endpoint and `TYPESAFE_API_KEY`. The response's `model` field records the model that answered. Re-evaluate your confidence thresholds before switching versions. See [TypeSafe models and aliases](https://docs.typesafe.ai/models) for current availability; gateway IDs are provider-specific.

## Adapt a different wire format

Suppose a service you control accepts `model_id`, `context`, and `prompts`, and returns `model_id`, `decisions`, and `token_usage`. The typed question and answer dictionaries inside those fields are unchanged.

The subclass below translates those field names. It calls the base payload builder first to retain question validation, and the base response parser after normalization to retain missing-answer and answer-type checks. Adapt these mappings to your provider's actual schema. If it uses different authentication, also override `build_headers()` as described in the [reference](/api/decision-model#extension-hooks).

## Complete runnable example

Save this as `custom_decision_model.py`, or use `examples/decision-models/code/custom_decision_model.py` in the documentation checkout.

```python
"""Use a pinned Jev, OpenRouter, or a provider with an envelope schema.

Every mode calls a real provider when executed. The custom schema is an
illustration, not a claim that a public service implements this protocol.
"""

import argparse
import json

from swarms import DecisionModel


class EnvelopeDecisionModel(DecisionModel):
    """Adapt context/prompts requests and decisions/token_usage responses."""

    def build_payload(self, state, questions):
        # Keep the base class's local validation before changing field names.
        payload = super().build_payload(state, questions)
        return {
            "model_id": payload.pop("model"),
            "context": payload.pop("state"),
            "prompts": payload.pop("questions"),
            **payload,
        }

    def parse_response(self, data, questions):
        # This provider keeps each typed answer's fields unchanged.
        normalized = {
            "model": data["model_id"],
            "answers": data["decisions"],
            "usage": data["token_usage"],
        }
        return super().parse_response(normalized, questions)


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument(
        "--provider", choices=("typesafe", "openrouter", "custom"),
        default="typesafe",
    )
    parser.add_argument("--base-url", help="Required for the custom provider")
    parser.add_argument("--model", help="Required for the custom provider")
    args = parser.parse_args()

    if args.provider == "openrouter":
        model = DecisionModel(
            base_url="https://openrouter.ai/api",
            endpoint="/v1/systemone",
            model_name="~typesafe/jev-latest",
            api_key_env="OPENROUTER_API_KEY",
        )
    elif args.provider == "custom":
        if not args.base_url or not args.model:
            parser.error("custom requires --base-url and --model")
        model = EnvelopeDecisionModel(
            base_url=args.base_url,
            endpoint="/evaluate",
            model_name=args.model,
            api_key_env="CUSTOM_DECISION_API_KEY",
        )
    else:
        model = DecisionModel(model_name="jev-1.13.0")

    try:
        result = model.run(
            state="Could you explain the difference between your plans?",
            questions={
                "team": {
                    "type": "choice",
                    "instructions": "Which team should handle this request?",
                    "criteria": {
                        "sales": "Plan comparisons and pricing",
                        "technical": "Software bugs and integrations",
                        "billing": "Invoices and existing payments",
                    },
                },
                "urgent": {
                    "type": "noul",
                    "instructions": "Does the request express urgency?",
                },
            },
        )
        print(json.dumps(result, indent=2))
    finally:
        model.close()


if __name__ == "__main__":
    main()
```

## Run the example

Run one mode at a time. Each invocation sends one evaluation request, plus any automatic retries:

```bash
# Uses TYPESAFE_API_KEY and a pinned direct TypeSafe model.
python custom_decision_model.py --provider typesafe

# Uses OPENROUTER_API_KEY and the gateway's Jev alias.
python custom_decision_model.py --provider openrouter
```

The custom mode is only usable with a real service that implements the illustrated schema. After configuring that service's URL, model name, and `CUSTOM_DECISION_API_KEY`, run:

```bash
python custom_decision_model.py --provider custom \
  --base-url "$DECISION_BASE_URL" \
  --model "$DECISION_MODEL_NAME"
```

The example uses `/evaluate` for that custom service. Update `endpoint` if your actual API uses another path. Do not point this adapter at TypeSafe or OpenRouter unchanged: their APIs expect the original field names.

## Inspect the result

The script prints the full normalized response, including the model, `team` and `urgent` answers, and usage. Capture your own run when testing a provider. No response values on this page are claimed to come from a live run.

The adapter can be tested offline with clearly synthetic fixtures to check field mapping and validation. Such tests verify client behavior; they do not establish that any remote service accepts the custom schema or that a model's decisions are accurate.

## Troubleshooting

- A missing key raises `ValueError` before a request. Check the environment variable for the selected mode
- A 401 response usually requires checking credentials at that provider
- A 404 can indicate a wrong base URL or endpoint
- A 422 response includes provider validation details; check the model ID and request schema
- A custom response missing one of the mapped fields raises `KeyError`; update the adapter to the actual schema
- A missing requested answer or mismatched answer type raises `RuntimeError` after normalization

The base client's retry and timeout behavior also applies to subclasses. Model discovery does not automatically use your custom URL: `list_models()` lists the framework's built-in providers. Consult your custom provider's model catalog separately.
